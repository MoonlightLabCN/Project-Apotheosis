alert() — expected on 0.1.9: the shell shows the message in the title bar, and script keeps running rather than pausing.
That is a deliberate deviation from the spec's modal semantics, not a missing feature: making it truly modal needs a nested run loop on the engine thread.
confirm() — BLOCKED on 0.2.0: always returns false (as if the user pressed Cancel). No prompt is shown. WebCore requires a synchronous answer; this port cannot wait on the UI thread. A nested engine run loop is the only correct path and is not shipped untested.
prompt() — KNOWN LIMITATION on 0.1.9: always returns null.
beforeunload — arm it, then navigate away. Expected on 0.1.9: no confirmation panel (canRunBeforeUnloadConfirmPanel() is false), navigation just proceeds.
